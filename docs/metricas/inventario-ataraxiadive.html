UAT no son casos pytest. Son 6 carpetas por SP (sp1, sp2, sp3, sp4, sp6, producción) con scripts de seed de datos + shell runners para validación HTTP manual contra un ambiente real — el patrón híbrido ya documentado en project_uat_pattern, no una omisión de conteo.

El código de test es más grande que el de producción. 46 230 SLOC de Python en tests/ contra 18 736 SLOC de producción en src/ — ratio ≈ 2.47:1. Sumando las 4 584 líneas Gherkin de los .feature (también código de test ejecutable vía pytest-bdd), el total sube a 50 814 SLOC de testing. Esta cifra es más alta que el 1.55:1 de test-to-code-ratio.md porque ese documento aplica un criterio más estricto (excluye fixtures/steps de soporte o cuenta solo statements ejecutables vía radon/coverage), mientras que este conteo suma toda línea no vacía/no comentario.
